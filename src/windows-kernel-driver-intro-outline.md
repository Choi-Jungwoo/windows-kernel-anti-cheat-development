# Windows 内核驱动入门

这份大纲安排进入反作弊驱动实现课程前需要掌握的基础。从 C/C++ 在机器上的表示开始，逐步讲到 Windows 怎样管理内存、处理请求，以及驱动怎样与系统配合。学完对应正文后，读者应能沿着一份驱动设计说明代码在哪执行、数据归谁所有，并找出越权访问或资源释放错误。是否可以进入下一阶段，以第 32 章的分析题为准；目前章节正文与题目材料尚待编写。

内容按微软的内核驱动架构文档、设备驱动接口（DDI）参考和 x64 应用二进制接口（ABI）文档组织。涉及处理器机制时，补充查阅体系结构手册。课程包含环境搭建、系统观察、原理讲解、伪代码和局部示例，不交付完整驱动，也不要求编译、加载、运行或测试驱动。

环境以 Windows 10 22H2 x64 为准，虚拟机可选 Hyper-V 或 VMware。读者从第 0 章搭建环境，再做各章安排的操作或分析练习。调试入门先观察已有系统，代码练习从独立的用户态小实验和驱动局部片段开始。示意输出会明确标注，不写成实测记录。

## 开始学习前的环境准备

### 第 0 章 从零搭建练习环境

这一章完成后，读者应拥有能恢复的 Windows 10 22H2 x64 目标虚拟机、可用的开发工具与调试器，并能连接目标系统查看基本信息。正文按下面的依赖顺序给出逐步操作，每步说明在哪台机器上做、需要什么权限、预期会看到什么，以及失败后怎样检查。

- **0.1 认识两台机器的分工**。解释宿主机、目标虚拟机、开发工具和调试器分别是什么。一台 x64 Windows 电脑运行工具并承载目标虚拟机可以组成教学环境；先给工具放置表，再解释为什么暂停目标系统时还需要能操作调试器。
- **0.2 检查电脑是否合适**。从查看系统版本和 CPU 架构开始，检查固件虚拟化开关、Hyper-V 所需系统版本、内存与磁盘预算。给出具体的教学资源分配示例，区分软件最低要求与同时运行工具和虚拟机所需余量。说明 ARM 宿主与本篇 x64 路线的差异，避免直接照抄配置。
- **0.3 准备安装材料与版本清单**。列出 Windows 10 22H2 x64 安装介质、虚拟化软件、Visual Studio、SDK、WDK 和 WinDbg 的官方来源。正文选定一组经过文档核对的具体版本，记录核对日期、宿主支持条件和目标系统，讲清下载页中的工具版本与来宾系统版本的区别。
- **0.4 安装开发工具**。按选定版本说明 Visual Studio 的 C++ 工作负载、MSVC、SDK、WDK 和驱动扩展如何安装。核对 SDK 与 WDK 的 build number，处理扩展或模板缺失。通过工具版本、头文件和库的安装位置检查配置，不以编译驱动判断安装成功。
- **0.5 Hyper-V 路线**。从启用功能和重启宿主开始，逐步创建虚拟交换机、选择虚拟机代数、分配处理器与内存、创建虚拟磁盘并挂载安装介质。说明每项选择的理由，再进入来宾安装。
- **0.6 VMware 路线**。以 Windows 宿主上的 VMware Workstation 为具体路线，说明版本与宿主兼容条件、安装、新建虚拟机、固件、磁盘、CPU、内存和网络选择。解释宿主已有 Hyper-V 或 VBS 时需要核对的运行条件，完成后进入与上一条路线相同的来宾检查。
- **0.7 安装并记录目标系统**。带读者完成 Windows 安装、账户与基础配置，使用 `winver` 和系统信息核对版本、构建号及 x64 架构。记录来宾的 Secure Boot、内存完整性和磁盘加密状态，保存初始配置，后续每次变更都能找到原值。
- **0.8 配置网络与材料传递**。解释 Hyper-V 虚拟交换机、VMware 的 NAT 与仅主机网络。区分下载材料需要的联网与调试需要的宿主来宾互通，记录各自地址、使用的网卡和防火墙规则，并说明如何把教学材料送入目标机。
- **0.9 创建恢复点并练习还原**。在修改启动配置前创建检查点或快照，先用无关紧要的标记文件练习一次恢复。说明快照、关机备份和导出各自保存什么，恢复后重新核对网络与调试配置；需要保留的作业放在恢复范围之外。
- **0.10 安装 WinDbg 与配置符号**。在调试主机安装调试器，配置微软符号服务器与本地缓存，解释网络下载、缓存目录和符号匹配各自解决什么问题。给出目录无权限、下载失败和符号不匹配的排查顺序。
- **0.11 建立内核调试连接**。Hyper-V 路线按微软文档配置 KDNET，先检查支持条件，再设置目标、宿主地址、端口和连接参数。VMware 路线说明虚拟串口与命名管道的配置，使用 KDNET 时先确认虚拟网卡支持。每条路线给出完整连接步骤，避免让初学者自行拼接不同方案。
- **0.12 处理启动配置与恢复**。区分内核调试开关、测试签名和实际加载驱动的条件。说明所选连接方案涉及的管理员权限、重启、安全配置变更及恢复步骤，只修改必要项目。目标无法启动、调试器一直等待时，能回到原配置或恢复点。
- **0.13 完成第一次观察**。连接来宾系统，暂停后查看版本、内核模块与符号，再恢复目标继续运行。逐条解释 `vertarget`、`lm`、`g` 等本次用到的命令和预期现象，保存读者自己的记录。这一步观察已有系统，不需要自编驱动。
- **0.14 准备后续练习与排错资料**。在开发机准备独立的用户态 C/C++ 小实验目录，用一个最小程序确认编译器、调试符号和断点可用。保存工具版本、虚拟机配置、连接记录与恢复方法；为虚拟化不可用、模板缺失、连接超时、符号下载失败分别提供排查入口。

### 第 1 章 重新看 C/C++ 中的数据与内存

- **1.1 整数与位运算**。二进制、十六进制、有符号和无符号数、补码、位掩码、移位，以及截断和扩展对结果的影响。
- **1.2 指针与边界**。地址、指针类型、数组退化、指针运算、空指针、悬空指针和缓冲区长度。把地址有效期与变量作用域分开理解。
- **1.3 结构体布局**。成员偏移、自然对齐、填充、联合体与位域。说明磁盘格式、通信格式和内存结构不能随意互相强转。
- **1.4 安全计算长度**。乘法与加法溢出、符号转换、元素数与字节数。分析“先算出错误的大小，再分配成功”的路径。
- **1.5 常见数据结构**。数组、侵入式链表、队列、环形缓冲区和查找表。讨论容量上限、删除时机与复杂度。

### 第 2 章 内核示例中的语言约定

- **2.1 常见 Windows 类型**。`ULONG`、`ULONG_PTR`、`SIZE_T`、`HANDLE`、`PVOID` 等类型的用途，指针宽度与整数宽度的区别。
- **2.2 返回状态**。`NTSTATUS`、`NT_SUCCESS`、成功与失败状态的传播。区分状态码、布尔值和用户态的 `GetLastError`。
- **2.3 字符串与链表**。`UNICODE_STRING` 的长度单位和缓冲区所有权，`LIST_ENTRY` 与 `CONTAINING_RECORD` 的阅读方法。
- **2.4 头文件与接口声明**。`ntddk.h`、`wdm.h`、`ntifs.h` 的使用语境，SAL 注解、输入输出参数和可选参数。依据 DDI 文档选择声明。
- **2.5 C++ 的使用边界**。名称修饰、`extern "C"`、构造与析构、模板、RAII，以及运行库依赖。明确 MSVC `/kernel` 禁用 C++ 异常与 RTTI，说明 `new`、`delete` 和标准库设施所需的运行库支持，不能照搬用户态用法。
- **2.6 生命周期与错误清理**。栈、全局状态与动态内存的区别；借用、转移所有权和成对释放。解释内核栈有限带来的约束。
- **2.7 结构化异常处理**。结构化异常处理（SEH）与 C++ 异常的区别，`__try`、`__except`、`__finally` 的用途。认识会引发异常的 DDI，分别追踪状态返回与异常路径上的资源清理；第 15、25 章用于分析用户缓冲区访问。

### 第 3 章 读懂 x64 汇编与调用约定

- **3.1 寄存器与指令**。通用寄存器、指令指针、标志寄存器，以及数据搬运、寻址、比较、条件跳转、调用和返回。
- **3.2 Windows x64 ABI**。参数寄存器、栈上传参、返回值、易失与非易失寄存器、shadow space 和栈对齐。浮点参数单独说明。
- **3.3 栈帧与展开**。函数序言、尾声、局部变量、保存寄存器和 unwind 信息。说明优化后源码与指令难以逐行对应的原因。
- **3.4 结构体访问**。从一小段反汇编识别成员偏移、数组索引和函数指针调用，区分加载地址与读取内容。
- **3.5 架构差异**。x86 与 x64 的指针和调用约定差别，WOW64 对通信结构的影响，MSVC x64 下内联汇编与 intrinsics 的使用条件。

### 第 4 章 从源文件到 PE 映像

- **4.1 编译与链接**。预处理、目标文件、符号解析、静态库、导入库，以及链接错误和加载错误的区别。
- **4.2 PE/COFF 布局**。DOS 头、PE 头、可选头、节表和数据目录，认识 `.text`、`.data`、`.rdata`、`.pdata` 等节的用途。
- **4.3 三种位置表示**。文件偏移、相对虚拟地址（RVA）和虚拟地址（VA）。结合文件与映像布局讨论换算的适用条件。
- **4.4 加载相关信息**。导入表、导出表、重定位、入口点、节权限与地址随机化。解释磁盘字节和加载后内存为什么可能不同。
- **4.5 调试符号**。PDB 与二进制匹配、公开符号与私有符号、源码位置和优化信息，避免把错误符号得到的字段解释当成事实。
- **4.6 解析边界**。读取头部、节表和目录前验证长度与范围，区分普通映像结构和签名等特殊目录的寻址规则。

### 第 5 章 CPU、设备与虚拟化的基本关系

- **5.1 特权机制**。用户态与内核态、特权指令、控制寄存器与模型专用寄存器（MSR），以及 CPU 特权级和 Windows 用户权限各自解决的问题。
- **5.2 中断与异常**。外部中断、处理器异常、系统调用、IDT 与异常处理入口。介绍 GDT、TSS 在 x64 环境中的基本角色。

**思考题**

在 Windows 10 22H2 x64 的一次完整内核启动中，某驱动配置为 `SERVICE_BOOT_START`。有人据此认为它的 `DriverEntry` 会在 Windows 内核获得控制权前执行，而且一定早于所有其他驱动。这两个判断是否成立？请分别说明映像加载与入口执行的阶段，以及启动类型能够保证到什么程度。

<details>
<summary>标准答案与解析</summary>

两个判断都不成立。Windows 加载器先把 BOOT_START 驱动映像放入内存，移交控制权之后，系统才在内核初始化过程中调用相应的 `DriverEntry`。文件已经在内存中，不能证明其中的入口已经执行。

BOOT_START 指定启动阶段，不能单独确定所有驱动之间的相对次序。分析顺序还要核对加载顺序组及系统规则；驱动已加载也不能证明它负责的设备或服务已经可用。[驱动加载顺序](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/specifying-driver-load-order)

</details>

**练习题**

沿用本章的 BOOT_START 概念和第 2 章的失败清理知识，分析下面这个假设的传统 NT 非 PnP 驱动初始化方案。它只用于纸面推演，不提供可运行驱动。

1. `DriverEntry` 先取得资源 A，再取得依赖 A 的资源 B。任一步失败都直接返回失败状态，没有释放动作。
2. 两项资源取得成功后，入口一直等待用户态服务 S 送来策略。题目已知 S 只能在入口返回后的后续启动阶段运行。
3. 作者试图通过 INF `Dependencies` 声明 S 来解决等待问题，或者改成在引导驱动重新初始化回调中继续无限等待 S。

题目约定，A、B 是驱动维持有效状态的必要资源，S 的策略仅供后续功能使用。请提交一张阶段与资源表，分别列出 A 失败、B 失败、两者成功但 S 未就绪时的返回与释放责任。再说明两种等待方案的问题、重新初始化回调的使用前提，以及怎样向后续调用者表示功能尚未就绪。

<details>
<summary>标准答案与解析</summary>

| 条件 | 本题中的处理 |
| --- | --- |
| A 取得失败 | 返回失败，没有已成功取得的资源需要释放 |
| A 成功、B 失败 | 先释放 A，再返回失败，不能期待卸载回调替入口收尾 |
| A、B 成功，S 未就绪 | 保留 A、B，完成必要入口初始化后返回成功，将依赖策略的功能标为未就绪 |
| 正常退出 | 停止使用相关资源后先释放 B，再释放 A，并结合第 18 章检查并发使用者 |

入口等待 S 会形成循环依赖，因为 S 要等入口返回后才可能启动。BOOT_START 的 INF `Dependencies` 不会替作者安排这个依赖；把无限等待移到重新初始化回调，也没有建立服务就绪的保证。[启动类型与依赖规则](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/specifying-driver-load-order)

若确实有适合重新初始化阶段的工作，应在确认 `DriverEntry` 将返回成功后注册回调，并让其上下文在使用期间有效。需要保留 `RegistryPath` 时保存字符串副本，不能留用入口的临时参数。这个回调不能充当用户态服务的就绪通知。[引导驱动重新初始化接口](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/nf-ntddk-ioregisterbootdriverreinitialization)

本题允许策略稍后到达，因此入口成功与策略功能可用可以分开表示。后续请求在未就绪时得到明确状态；第 21 章再讨论通信细节。答案须覆盖失败清理和服务始终不出现的情况，不能把“驱动加载成功”报告成“全部功能已经工作”。

</details>

### 第 26 章 时间、日志与事件记录

- **26.2 诊断方式**。`DbgPrintEx`、WPP 和 ETW 的用途，级别、类别、提供者与消费者的基本关系。
- **26.3 记录内容**。请求标识、状态、线程与进程信息、驱动版本和丢失计数，避免从单个字段推断过多。
- **26.4 并发记录**。顺序、重入、缓冲区上限、采样、限速和记录开销，高频路径中的日志可能改变观察到的行为。
- **26.5 信息范围**。诊断所需信息与敏感数据、内核地址等内容的区别，读取记录的权限和保留期限。

**拟用示例**

阅读一份明确标为示意的事件表，区分失败发生顺序与日志写入顺序。存在丢失计数时，说明哪些结论仍有依据。

## 第七部分 安全与工程判断

### 第 27 章 启动、签名与内核保护

- **27.1 启动过程**。UEFI、引导程序、Windows 加载器、内核和启动阶段驱动的基本关系。把第 13 章的 BOOT_START 放回完整启动过程，区分各阶段执行者及其信任前提。
- **27.2 签名的职责**。哈希、数字签名、证书与信任链，解释文件完整性和发布者身份；比较目录签名、测试签名与正式发布，区分签名和代码本身的正确性。
- **27.3 加载条件**。操作系统版本、启动配置、签名策略与硬件状态如何共同影响驱动加载，查阅与目标环境相符的文档。
- **27.4 系统保护机制**。Secure Boot、代码完整性、Kernel Patch Protection、虚拟化安全（VBS）和内存完整性（HVCI）的作用范围。结合第 5 章理解 Windows 如何利用 hypervisor 提供隔离。
- **27.5 兼容性约束**。可写与可执行内存、动态代码、内核结构修改和未文档化偏移，说明这些做法与系统约束的冲突。
- **27.6 信任假设**。内核权限、hypervisor、固件与设备访问属于不同的能力范围，明确一个驱动能观察和依赖什么。
- **27.7 Windows 的虚拟化隔离**。虚拟安全模式（VSM）、虚拟信任级别（VTL）、VTL0 与 VTL1，以及普通内核与安全内核的关系。区分 VTL、Ring 和 VMX 执行状态，解释普通内核驱动受到的访问限制。检查 Hyper-V、VBS 与自研监控器的兼容条件，不能从支持 VT-x 或 AMD-V 直接推定它们能共同运行。
- **27.8 BOOT_START 与 ELAM 的区别**。介绍提前启动反恶意软件（Early Launch Antimalware，ELAM）的职责及专用要求。普通 BOOT_START 驱动不会因为 `Start=0` 就取得 ELAM 身份或其初始化次序；测试签名也不能替代 ELAM 的专用签名与准入条件。入门要求理解两者关系，ELAM 的实现不作为本篇前置要求。

**拟用示例**

对照两份安全配置，分析同一驱动在加载条件和内存使用约束上的差异。不给出绕过系统保护的实现。

虚拟化隔离参阅微软的 [虚拟安全模式与 VTL](https://learn.microsoft.com/en-us/virtualization/hyper-v-on-windows/tlfs/vsm)。

ELAM 参阅微软的 [提前启动反恶意软件概述](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/early-launch-antimalware)、[ELAM 驱动要求](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/elam-driver-requirements) 和 [ELAM 准入与签名条件](https://learn.microsoft.com/en-us/windows-hardware/drivers/install/elam-prerequisites)。

### 第 28 章 WinDbg 与证据阅读

- **28.1 调试方式**。用户态调试、内核调试、实时连接和转储分析各自能看到什么。
- **28.2 符号与上下文**。符号路径、PDB 匹配、模块版本、当前进程和线程，识别上下文不一致导致的错误解释。
- **28.3 基本阅读工具**。断点、单步、寄存器、调用栈、反汇编、内存和类型显示。围绕 `k`、`r`、`u`、`dt`、`lm` 说明用途。
- **28.4 驱动相关对象**。进程、线程、设备对象、IRP、锁和内存池的观察思路，从现象选择需要查看的对象。
- **28.5 观察的限制**。优化、缺失页面、不完整转储、异步调用栈与系统暂停带来的影响。

**拟用示例**

阅读一份标为示意的调用栈和模块表，先确认符号与线程上下文，再指出当前资料能支持的判断及仍缺少的信息。

### 第 29 章 崩溃、挂起与验证方法

- **29.1 故障种类**。异常、Bug Check、死锁、长时间等待、资源耗尽和静默数据损坏，分别需要哪些证据。
- **29.2 转储阅读顺序**。停止码、参数、故障指令、调用栈和相关对象。`!analyze -v` 给出线索后，还要追溯资源与执行条件。
- **29.3 典型错误机制**。错误 IRQL 下访问、释放后使用、池越界、重复完成请求和卸载竞态，区分出错位置与最早的错误动作。
- **29.4 Driver Verifier**。内存、I/O、IRQL 和死锁等检查类别，说明检测能力、覆盖限制和主动触发崩溃的可能。
- **29.5 源码分析与场景推演**。编译器诊断、SAL、静态分析，以及分配失败、请求取消和并发退出的分析方法。
- **29.6 恢复与记录**。实际验证前应准备什么，发生启动问题时如何恢复；本课程仅讲解方法，不产生驱动实测结论。

**拟用示例**

为一次“卸载后仍有延迟工作访问旧状态”的崩溃列出调查顺序，说明还需哪些记录才能确认原因。

### 第 30 章 性能、兼容性与发布常识

- **30.1 性能成本**。回调频率、每次工作量、池分配、锁竞争、排队和日志的累计成本。
- **30.2 评价指标**。CPU 时间、等待时间、请求延迟分布、队列长度、丢失事件和内存上限，说明平均值可能遗漏的问题。
- **30.3 测量条件**。负载、系统配置、符号与构建方式、采样误差和调试器干扰，设计比较时固定需要控制的变量。
- **30.4 兼容性维度**。目标系统构建号、CPU 与虚拟化设置、HVCI、WOW64、其他驱动、睡眠恢复和多客户端访问。
- **30.5 发布与恢复**。驱动包版本、接口协议版本、签名、升级、卸载、回滚与旧客户端兼容。理解正常路径以外的部署责任。
- **30.6 成果的表述**。文档契约、纸面推演、源码检查与运行数据分别能证明什么，避免把它们互相替代。

**拟用示例**

为一个事件队列列出性能与兼容性评价表，分析如何发现队列积压及如何比较两种处理方式，不填入未经测量的数字。

## 第八部分 综合阅读与进入反作弊课程前的准备

### 第 31 章 怎样阅读一份驱动示例

- **31.1 先看契约**。确认驱动模型、目标系统、对外接口和假设，查清示例省略了哪些部分。
- **31.2 沿生命周期阅读**。从初始化进入公开入口，再追踪清理；为每种资源列出取得和释放的位置。
- **31.3 跟踪请求与数据**。输入来源、权限检查、缓冲区复制、状态修改、结果返回与最后一次访问。
- **31.4 标注执行条件**。每个入口的 IRQL、线程上下文、持锁状态和可能发生的并发，调用链上的条件不能丢失。
- **31.5 核对文档**。真实 DDI 的参数、返回值、版本要求、所有权和注销保证；对未文档化内容保留不确定性。
- **31.6 找出隐含前提**。单客户端、无并发、永不失败或事件不丢失等简化，分析这些前提改变后的后果。

**拟用示例**

提供若干互相独立的局部片段，让读者填写资源表与调用条件表。示例保留必要省略标记，不组合成可构建驱动。

### 第 32 章 综合场景与基础掌握清单

综合场景设定为“用户态程序查询一份由内核事件更新的有界状态表”。只讨论操作系统语义、通信与资源管理，不设计作弊检测规则。

- **32.1 组件职责**。划分用户态程序、驱动入口、事件记录和延迟处理的职责，解释每项职责的执行位置。
- **32.2 资源与状态**。列出对象引用、缓冲区、请求和队列的所有者，说明停止期间允许哪些状态变化。
- **32.3 权限与协议**。判断谁能打开接口，输入如何验证，返回数据有哪些长度和版本约束。
- **32.4 故障推演**。逐项分析用户进程退出、队列已满、分配失败、重复请求、事件丢失和驱动停止。加入查询与通知并发、PID 复用，以及用户态程序重连时旧请求和旧状态的处理。
- **32.5 证据与边界**。说明纸面分析得出了什么，哪些性能与可靠性结论必须留待实际项目验证。

进入反作弊专题前，读者可以查阅 DDI 文档，独立完成下表的纸面任务。正文需要提供题目片段、条件和参考分析，不能只列问题名称。每项答案都要指出依据；资料不足时写明缺少的条件。

| 基础能力 | 拟设分析题与交付物 | 答案必须包含 | 对应章节 |
| --- | --- | --- | --- |
| 数据与机器表示 | 给定跨位数消息、长度计算、简化汇编和 PE 节表，写出布局及地址换算 | 字段宽度与填充、计算溢出条件、参数位置，以及 RVA 是否有对应文件数据 | 1 至 5 |
| 执行环境 | 给一次用户请求、一个通知回调和一个 DPC 分别填写执行条件表 | 模式、权限、进程与线程上下文、IRQL 和 APC 条件；逐项判断能否等待及访问分页内容 | 6、7、10、14 |
| 内存有效性 | 将请求中的用户地址交给延迟工作，标出每次访问所需的前提 | 地址空间、长度、数据捕获时机、SEH、MDL 的作用和限制，以及缓冲区最后一次使用 | 2、8、14、15、25 |
| 对象生命周期 | 推演用户关闭句柄、进程退出、PID 被复用的过程，填写引用表 | 数值标识与进程实例的区别、对象引用的取得及释放，不能用对象仍存在推断进程仍运行 | 7、9、18 |

| 并发与退出 | 推演回调、队列和停止操作同时发生的情况，列出状态与资源变化 | 新工作何时被拒绝、排队及正在执行的工作由谁收尾、等待时是否持锁，以及最终释放条件 | 16 至 18 |
| 通知契约 | 将查询结果和通知合并成状态表，再插入进程退出、PID 复用、事件丢失与客户端重连 | 回调上下文、借用数据有效期、注销保证；注册窗口内可能的遗漏和重复、重建条件与仍未知的状态 | 7、21、24 至 26 |
| 系统保护 | 对照两份环境清单与一个局部设计，说明加载和兼容性条件，并推演一次两级地址转换 | 签名与启动配置、HVCI 约束和接口版本；区分 Ring、VMX 状态与 VTL，解释 EPT/NPT 权限、嵌套条件和各层能力范围 | 5、10 至 12、27 |
| 诊断与工程判断 | 阅读示意调用栈、符号信息和含丢失记录的事件表，写出调查顺序 | 符号与上下文是否匹配、现象与原因的区别、还需哪些证据，以及评估性能、兼容性和恢复所需的条件 | 26、28 至 31 |

具体硬件协议、完整文件系统或网络过滤器开发也属于各自的深入课程。本篇先讲清工作位置、权限和依赖，具体实现按后续专题补充。
